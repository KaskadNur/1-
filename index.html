1Язык запросов: механизм запросов

Уровень 1 — база

Для чего нужны запросы в 1С и какова общая схема их выполнения?
Запрос — это способ «спросить базу данных» на специальном языке. Простым языком: мы говорим системе «дай мне вот эти данные, вот с такими условиями, сгруппированные вот так», и она быстро их возвращает.
Это выгоднее, чем читать объекты в цикле, потому что вся работа происходит внутри СУБД (базы данных) — одной командой. Запросы применяют везде, где нужно показать или посчитать данные: отчёты, обработки, проведение документов.

Общая схема (всегда одна и та же):
1) создать объект Запрос;
2) написать текст запроса в свойство Запрос.Текст;
3) если в тексте есть параметры (&Имя) — передать их значения методом УстановитьПараметр();
4) выполнить запрос методом Выполнить() — получаем РезультатЗапроса;
5) из результата взять данные: Выбрать() (обойти по строкам) или Выгрузить() (получить таблицу значений).

Уровень 2 — практика

Назовите основные конструкции синтаксиса языка запросов: операторы, агрегатные функции, группировки, итоги.
Запрос — это текст, состоящий из нескольких частей. Обязательная часть только одна — описание запроса (откуда берём и что выбираем). Остальные части подключаются по необходимости:
ВЫБРАТЬ <поля> ИЗ <источник> ГДЕ <условия> // описание запроса (обязательно) ОБЪЕДИНИТЬ ВСЕ ... // объединение нескольких запросов УПОРЯДОЧИТЬ ПО <поля> // упорядочивание результата АВТОУПОРЯДОЧИВАНИЕ // «как удобно системе» СГРУППИРОВАТЬ ПО <поля> // группировка ИТОГИ <агрегаты> ПО <поля> // итоги
Источником (ИЗ) могут быть: таблицы справочников/документов, виртуальные таблицы регистров, подзапросы, временные таблицы, таблицы значений (переданные параметром).
Агрегатные функции — «счётчики» по группам строк: СУММА() (сумма), МАКСИМУМ()/МИНИМУМ() (макс/мин), СРЕДНЕЕ() (среднее), КОЛИЧЕСТВО() (сколько строк), КОЛИЧЕСТВО(РАЗЛИЧНЫЕ …) (сколько разных значений).
Группировка (СГРУППИРОВАТЬ ПО) — «схлопнуть» много строк в несколько, посчитав по каждой группе агрегаты. Итоги (ИТОГИ … ПО) — наоборот: к выборке добавляются служебные строки с промежуточными и общими суммами.
ВЫБРАТЬ Склад, Номенклатура, СУММА(Количество) КАК Кол ИЗ РегистрНакопления.Остатки.Остатки КАК Ост СГРУППИРОВАТЬ ПО Склад, Номенклатура ИТОГИ СУММА(Количество) ПО (Склад), ОБЩИЕ
Простыми словами: группировка убирает детализацию (строки сливаются в группы), а итоги добавляют «итого по группам» и «общий итог».

Уровень 3 — глубокое понимание

Перечислите все виды соединений таблиц, их различия и случаи применения.
1. ВНУТРЕННЕЕ СОЕДИНЕНИЕ — остаются только строки, нашедшие себе «пару» в обеих таблицах. Используется, когда связь обязательна: документ → его строки, элемент → его владелец.
2. ЛЕВОЕ СОЕДИНЕНИЕ — все строки левой таблицы; если пары в правой нет, поля правой заполняются NULL. Используется для необязательной информации: заказ → менеджер, которого может не быть.
3. ПРАВОЕ СОЕДИНЕНИЕ — зеркально левому (все строки правой таблицы).
4. ПОЛНОЕ СОЕДИНЕНИЕ — все строки обеих таблиц (недостающее — NULL). Применяется редко, обычно при сведении двух независимых списков.
Также бывает Перекрестное соединение Суть: Оно берет каждую строку из первой таблицы и принудительно соединяет её со всеми строками из второй таблицы. Это называется декартовым произведением.Результат: Если в Таблице А у вас 5 строк, а в Таблице Б — 4 строки, на выходе вы получите ровно 20 строк (\(5 \times 4\)). Никаких NULL здесь не возникает, так как связываются абсолютно все строки.

Важно про NULL: в левом/правом соединении поля «пустой» стороны равны NULL, поэтому в условиях корректно использовать ЕСТЬNULL() или проверку ИЛИ Поле ЕСТЬ NULL. Различие на практике: внутреннее — только связанные данные, левое — ещё и «сироты» слева.

2Язык запросов: работа с запросами во встроенном языке

Уровень 1 — база

Как пользоваться конструктором запроса? Каков синтаксис простейшего запроса?
Конструктор вызывается в тексте запроса (в модуле) через контекстное меню — пункт «Конструктор запроса…» (правой кнопкой мыши). В нём на вкладке «Таблицы и поля» выбираются источники и поля, далее настраиваются связи, условия, группировка, ВСЕ ПОЛЯ Конструктор генерирует готовый текст запроса.
Простейший запрос:
Запрос = Новый Запрос; Запрос.Текст = "ВЫБРАТЬ | Номенклатура.Ссылка, | Номенклатура.Наименование |ИЗ Справочник.Номенклатура КАК Номенклатура"; Результат = Запрос.Выполнить(); Выборка = Результат.Выбрать(); Пока Выборка.Следующий() Цикл Сообщить(Выборка.Наименование); КонецЦикла;

Уровень 2 — практика

Как задать связи между таблицами? Что такое объединение? Как создать пакетный запрос с временными таблицами?
Связи задаются в конструкторе на вкладке «Связи» либо в тексте:
ВЫБРАТЬ Т.Ссылка ИЗ Справочник.Товары КАК Т ЛЕВОЕ СОЕДИНЕНИЕ Справочник.ЕдИзм КАК Е ПО Т.ЕдИзм = Е.Ссылка
Объединение (ОБЪЕДИНИТЬ ВСЕ) — вертикальное «склеивание» двух выборок с одинаковыми колонками в одну (например, продажи из разных документов). ОБЪЕДИНИТЬ (без ВСЕ) дополнительно убирает дубли.
Пакетный запрос — несколько запросов в одном тексте, разделённых точкой с запятой «;». Промежуточные результаты кладутся во временные таблицы оператором ПОМЕСТИТЬ:
ВЫБРАТЬ Т.Номенклатура, СУММА(Т.Количество) КАК Кол ПОМЕСТИТЬ ВТ_Продажи ИЗ Документ.Продажа.Товары КАК Т СГРУППИРОВАТЬ ПО Т.Номенклатура; ВЫБРАТЬ ВТ.Номенклатура, ВТ.Кол ИЗ ВТ_Продажи КАК ВТ
Временная таблица индексируется по полям первого запроса (можно добавить индекс через ИНДЕКСИРОВАТЬ ПО). Выполняется пакет методом ВыполнитьПакет(); результат — массив результатов по пакетам. Временные таблицы живут в рамках сеанса подключения.

Уровень 3 — глубокое понимание

Как обойти выборку результата запроса? Как передать таблицу значений параметром? Как отлаживать запросы?
Обход выборки:
Выборка = Результат.Выбрать(); Пока Выборка.Следующий() Цикл // обращение: Выборка.Ссылка, Выборка.Сумма КонецЦикла;
При небольшом объёме удобно Результат.Выгрузить() — получить таблицу значений. Для пакета: Результаты = Запрос.ВыполнитьПакет(); затем Результаты[0].Выбрать().
Таблица значений как параметр: в тексте запроса источник указывается как &ТабЧасть, на сервере параметр устанавливается методом УстановитьПараметр():
Запрос.УстановитьПараметр("ТабЧасть", ТаблицаЗначений); // в тексте: ВЫБРАТЬ Т.Номенклатура ИЗ &ТабЧасть КАК Т
Ограничение — состав колонок таблицы значений должен быть известен на этапе разбора запроса. Индексы по колонкам ТЗ платформа создаёт автоматически.
Отладка запросов: обработка «Консоль запросов» (в типовых поставках): в ней виден текст, параметры, результат, а главное — план запроса (аналог EXPLAIN), по которому видно, какие индексы задействованы и где «тяжёлые» места. Дополнительно: вывод текста в окно сообщений, выполнение в блоке «Попытка…Исключение», разбиение пакета на этапы для локализации ошибки.

3Язык запросов: оптимизация запросов

Уровень 1 — база

Как в общих чертах должен строиться запрос?
Запрос должен извлекать минимум данных: только нужные поля, отборы — ещё на уровне источника (в ГДЕ или параметрами виртуальных таблиц), а не «отрезать лишнее» после выборки. Соединения — с ограничением обрабатываемых строк; чтение — по индексам; тяжёлые многошаговые расчёты — через временные таблицы. Один хорошо построенный запрос всегда лучше сотни мелких запросов в цикле.

Уровень 2 — практика

Назовите общие рекомендации построения оптимального запроса и способы их реализации.
1) Использовать виртуальные таблицы с параметрами (Период, Условие), а не читать физические таблицы целиком.
2) Задавать отборы как можно раньше — в ГДЕ и в параметрах ВТ, а не фильтровать готовую выборку в цикле.
3) Выбирать только нужные поля, избегать «звёздочки» (*).
4) Не использовать подзапросы там, где достаточно соединения.
5) Для сложных многошаговых расчётов применять временные таблицы (они индексируются по первому полю).
6) Не применять функции к полям в условиях — ГДЕ ВЫРАЗИТЬ(Т.Поле, …) «убивает» индекс.
7) Не выполнять запросы внутри цикла по строкам выборки (проблема N+1) — лучше один запрос с соединением.
8) Использовать АВТОУПОРЯДОЧИВАНИЕ и сортировку только там, где они действительно нужны.

Уровень 3 — глубокое понимание

Как работает индексирование таблиц? Каковы общие рекомендации по индексам?
Индекс — служебная структура СУБД, ускоряющая поиск, соединение и сортировку по полям. В 1С индексы настраиваются в первую очередь для регистров: на вкладке «Измерения» у измерения включается признак «Индексировать»; также возможны составные индексы по нескольким измерениям.
Рекомендации:
— индекс оправдан, если поле часто участвует в отборах и соединениях;
— в составном индексе первыми идут наиболее избирательные (различающие) поля;
— индексировать поля, по которым выполняется сортировка;
— слаборазличимые поля (булево, поле с 2–3 значениями) индексировать нецелесообразно;
— виртуальные таблицы регистров автоматически используют индекс измерений, поэтому отборы по измерениям быстрые;
— каждый лишний индекс замедляет запись — нужен баланс между скоростью чтения и записи.

4Оперативный учёт: регистр накопления

Уровень 1 — база

Какие виды регистра накопления бывают и для чего они применяются?
Два вида: «Остатки» и «Обороты».
— Регистр остатков отвечает на вопрос «сколько есть сейчас»: хранит состояние на момент времени (остатки товаров на складе, деньги в кассе). Его виртуальные таблицы: Остатки, Обороты и ОстаткиИОбороты.
— Регистр оборотов отвечает на вопрос «сколько было за период»: хранит итоги (продажи за месяц, выработка). Его виртуальная таблица: Обороты.
Применяются в оперативном учёте — когда документы (продажи, приходы, расходы) меняют складские и денежные показатели.

Уровень 2 — практика

Какие виртуальные таблицы есть у регистра накопления? Опишите структуру остаточного и оборотного регистра.
Виртуальные таблицы остаточного РН:
— Остатки — остатки на период, параметры: Период, Условие, Граница, МетодДополненияПериодичности, НачалоПериода, КонецПериода;
— ОстаткиИОбороты — дополнительно обороты за период.
Виртуальная таблица оборотного РН: Обороты — параметры: Периодичность, Период, Условие, Граница, МетодДополненияПериодичности.
Структура: Измерения — разрезы учёта (склад, номенклатура), Ресурсы — числовые показатели (количество, сумма). У остаточного РН в ВТ ОстаткиИОбороты появляется ресурс вида ИмяРесурсаОборот. У оборотного РН ресурсы — сами обороты за период, детализация задаётся периодичностью.

Уровень 3 — глубокое понимание

Что такое таблица итогов и таблица движений? Чем отличаются итоги остаточного и оборотного РН? Как работает индексация регистра накопления?
Таблица движений — физическая таблица записей (регистратор, период, вид движения, измерения, ресурсы). Таблица итогов — агрегированные данные, хранящиеся для быстрого получения остатков/оборотов; пересчитывается при записи движений (проведении).
Отличие итогов: у остаточного РН итоги — остатки на момент времени (движения до даты включительно), у оборотного РН — суммы движений за периоды (с заданной периодичностью). Виртуальные таблицы читают именно таблицу итогов, поэтому работают быстро.
Индексация: измерения регистра индексируются (признак «Индексировать»); состав индексов таблицы итогов определяется набором измерений. Отборы по измерениям в виртуальных таблицах используют индекс автоматически, поэтому важно, чтобы в условиях участвовали измерения (а не только ресурсы). Чем больше измерений «разворачивается» в запросе, тем больше строки итогов — отсюда важность продуманного набора измерений.

5Оперативный учёт: заполнение таблиц регистров накопления

Уровень 1 — база

Как воспользоваться конструктором движений?
Конструктор движений вызывается в обработчике проведения (процедура ОбработкаПроведения): установить курсор на текст под словом «Движения» и выбрать в контекстном меню «Конструктор движений…». Мастер предложит выбрать регистр документа, сопоставить поля табличной части документа с полями регистра, указать период и признак «Записывать движения». На выходе будет сгенерирован код:
// Движения: Если Запрос.Пустой() Тогда Возврат; КонецЕсли; Движения.Регистр.Очистить(); СтрокаДвижения = Движения.Регистр.Добавить(); СтрокаДвижения.Период = Дата; СтрокаДвижения.Склад = Склад; СтрокаДвижения.Номенклатура = ТЧ.Номенклатура; СтрокаДвижения.Количество = ТЧ.Количество; // ... Движения.Записать();
В текст добавляется вызов конструктора запроса, который заполняет движения из данных документа.

Уровень 2 — практика

Как формируются движения регистра накопления? Как записать данные в РН без использования свойства «Движения»?
Формирование движений выполняется в обработчике проведения: через свойство объекта Движения.ИмяРегистра получается набор записей, в него добавляются строки (Добавить()), заполняются поля, вызывается Записать(). Период по умолчанию берётся из даты документа.
Запись без свойства «Движения» (например, из обработки или когда у документа нет регистратора): используется объект РегистрыНакопления.ИмяРегистра.СоздатьНаборЗаписей():
НаборЗаписей = РегистрыНакопления.Остатки.СоздатьНаборЗаписей(); НаборЗаписей.Отбор.Регистратор.Установить(СсылкаНаДокумент); НоваяЗапись = НаборЗаписей.Добавить(); НоваяЗапись.Период = СсылкаНаДокумент.Дата; НоваяЗапись.ВидДвижения = ВидДвиженияНакопления.Приход; НоваяЗапись.Склад = Склад; НоваяЗапись.Количество = 10; НаборЗаписей.Записать();
Важно: у записей обязательно указывается регистратор (отбор), иначе платформа не позволит записать. Таблица записей заполняется через Добавить() либо из таблицы значений методом Загрузить().

Уровень 3 — глубокое понимание

Каковы механизмы заполнения таблицы итогов остаточного и оборотного РН? Что такое режим разделения итогов?
Механизм заполнения таблицы итогов: при записи движений (проведении документа) платформа пересчитывает агрегаты — для остаточного РН остатки на моменты времени, для оборотного — обороты по периодам. Так работают виртуальные таблицы: они читают готовые итоги, поэтому отвечают быстро.
Режим разделения итогов (признак «Разделение итогов» на регистре) — механизм, при котором итоги дополнительно разбиваются в разрезе указанных измерений. Нужен, когда часть итогов может считаться «в будущем» или для параллельного расчёта по независимым разрезам (например, по филиалам). При включённом разделении итогов по измерению виртуальные таблицы корректно считают остатки/обороты с учётом этого разреза.

6Оперативный учёт: получение данных регистра накопления

Уровень 1 — база

Как получить движения регистра накопления?
Запросом к физической таблице движений:
ВЫБРАТЬ Т.Период, Т.Регистратор, Т.Номенклатура, Т.Количество ИЗ РегистрНакопления.Остатки.Движения КАК Т ГДЕ Т.Регистратор = &СсылкаНаДокумент
Объектной моделью: РегистрыНакопления.Остатки.СоздатьНаборЗаписей(), установить отбор по регистратору и выполнить Выбрать()/Выгрузить().

Уровень 2 — практика

Как правильно получить остатки/обороты? Какая объектная модель получения остатков? Как правильно применять отборы в виртуальных таблицах РН?
Остатки запросом:
ВЫБРАТЬ Ост.Номенклатура, СУММА(Ост.Количество) КАК Остаток ИЗ РегистрНакопления.Остатки.Остатки( &Дата, Склад = &Склад) КАК Ост СГРУППИРОВАТЬ ПО Ост.Номенклатура
Объектно: РегистрыНакопления.Остатки.ОстаткиНаДату(Дата, Условие, Граница) — возвращает таблицу значений. Обороты: РегистрНакопления.Продажи.Обороты(Pериод, Периодичность, Условие).
Правила отборов в ВТ: условия обязательно передавать параметром Условие — тогда отбор выполняется внутри СУБД, а не после выгрузки. Условия строятся по измерениям (склад, номенклатура) через полные пути: Склад = &Склад И Номенклатура.Владелец = &Группа. Для списка значений — Номенклатура В (&Список). Отбор по полям, не входящим в индексы ВТ, замедляет запрос — таких условий следует избегать.

Уровень 3 — глубокое понимание

Когда использовать запрос, а не объектную модель? Что такое агрегаты? Что такое граница и момент времени, для чего они нужны?
Запрос — для массовых расчётов (отчёты, обработка тысяч строк): выполняется на сервере, читает только нужные колонки, использует индексы и виртуальные таблицы. Объектная модель — для точечных обращений из клиентского кода (получить остаток одной позиции): проще в написании, но медленнее и загружает данные клиенту.
Агрегаты (настройка «Агрегаты» на регистре, объекты РегистрыНакопления.Имя.Агрегаты) — предварительно рассчитанные агрегированные значения по заданным измерениям. Нужны для мгновенных ответов на типовые вопросы вида «всё по складу за месяц» без обращения к итогам/движениям.
Граница — параметр виртуальных таблиц, управляющий включением движений: например, Граница = МоментВремени позволяет получить данные «как было на момент X». Момент времени — идентификатор конкретной точки времени (содержит дату/время и ссылку на документ, а также признак включения/исключения движений этого документа). Нужен для корректного получения остатков при проведении «задним числом»: позволяет учесть только документы, проведённые до указанного момента. Используется в объектных методах получения остатков на дату.

7Бухгалтерский учёт: план счетов и его свойства

Уровень 1 — база

Что такое план счетов и каково его назначение?
План счетов — конфигурационный объект, описывающий перечень счетов бухгалтерского учёта: код, наименование, признаки ведения учёта. Назначение — задать структуру бухгалтерского учёта: какие счета существуют (активные, пассивные, с субсчетами), ведётся ли по ним аналитический (субконто), валютный, количественный учёт. Фактически план счетов — «костяк», на который опирается регистр бухгалтерии.

Уровень 2 — практика

Назовите свойства плана счета.
Основные свойства плана счетов:
— Код (маска и длина, например, три цифры для счёта + субсчета);
— Наименование (длина, представление);
— Вид плана счетов — иерархический: счета образуют иерархию «счёт → субсчета»;
— данные счетов: коды, наименования, признак «Вести по субсчетам»;
— настройки учёта: валюта (вести по валютам), количество (количественный учёт), сумма (суммовый учёт);
— измерение Субконто — набор измерений (разрезов) для аналитического учёта по счету;
— ведение итогов (ВестиИтоги по счетам/субсчетам).

Уровень 3 — глубокое понимание

Что такое аналитический учёт и субконто? Какие бывают признаки учёта субконто? Каковы особенности написания запросов с отборами по счету?
Субконто — измерение (разрез), по которому ведётся аналитический учёт на счете (например, субконто «Номенклатура», «Контрагенты»). Один счёт может иметь несколько субконто — в наборе «Субконто» плана счетов (до N измерений, обычно до 5). Для каждого субконто задаётся тип значения (вид: справочник, документ и т.д.).
Признаки учёта субконто:
— вид субконто (какой объект/тип используется для аналитики);
— признак использования на конкретном счете (счёт ведёт/не ведёт данное субконто) — это признак счёта (флаг «Использовать» в свойствах элемента плана счетов);
— признак ведения итогов по субконто на регистре бухгалтерии (итоги по измерению субконто);
— у субконто бывает признак необязательности (разрешено пустое значение).
Особенности запросов с отборами по счету:
1) отбор в виртуальных таблицах регистра бухгалтерии делается через параметр Условие: Счет = &Счет или Счет В ИЕРАРХИИ(&ГруппаСчетов) (чтобы учесть субсчета).
2) отбор по субконто учитывает «признак ведения» — делается через условие с проверкой признака:
(Субконто1 = &Значение ИЛИ НЕ ВЫРАЗИТЬ(Счет.ВестиСубконто1, БУЛЕВО))
3) в ВТ остатков регистра бухгалтерии используется специальная настройка «ВестиИтогиПоКорреспонденции», а отбор по счету — по полям СчетДт/СчетКт или Счет.

8Бухгалтерский учёт: регистр бухгалтерии

Уровень 1 — база

Для чего нужен регистр бухгалтерии?
Регистр бухгалтерии предназначен для хранения проводок бухгалтерского учёта — записей вида «счёт дебета → счёт кредита» с суммами и аналитикой (субконто). На его основе формируются остатки и обороты по счетам без написания сложных программных алгоритмов. Фактически это аналог «главной книги» и «журнала операций».

Уровень 2 — практика

Каковы основные свойства регистра бухгалтерии? Что такое корреспонденция?
Основные свойства:
— связанный план счетов (ПланСчетов);
— измерение Субконто (набор разрезов аналитики, до 5);
— ресурсы: Сумма, Количество, СуммаВВалюте (если ведётся валютный учёт);
— признак ВедениеИтогов (по счетам, по корреспонденции, по субконто);
— признак Корреспонденция — ведётся ли учёт по корреспонденции (поля СчетДт/СчетКт) или по одному счёту (поле Счет).
Корреспонденция — связка «Дебет → Кредит»: каждой проводке соответствует пара счетов. Учёт по корреспонденции позволяет получать обороты «Дт счета А — Кт счета Б» и строить аналитические отчётности (АВД, шахматные ведомости).

Уровень 3 — глубокое понимание

Какие виртуальные таблицы есть у регистра бухгалтерии? Каковы свойства измерений и ресурсов?
Виртуальные таблицы регистра бухгалтерии (по книге):
— Остатки — остатки по счетам на дату («сколько на счете»);
— Обороты — обороты по счетам за период («сколько прошло» через счёт);
— ОстаткиИОбороты — и остатки, и обороты вместе.
Параметры ВТ: Период, Периодичность, Условие, Граница, МетодДополненияПериодичности, а у остатков — ВключаяОборотыДоПериода и ВключаяОборотыВПериоде. Отбор по счёту/субконто — через Условие.
Измерения и ресурсы: измерениями выступают субконто (они же — измерения регистра), ресурсами — значения Сумма, СуммаОстаток, СуммаПриход, СуммаРасход, КоличествоОстаток и т.д. Свойства ресурсов: тип (число), признак ведения итога (итог по ресурсу). Свойства измерений субконто: тип значения (вид субконто), признак «Индексировать». Остатки по счету в ВТ рассчитываются с учётом знака движения: для активных счетов дебет увеличивает остаток, для пассивных — кредит; это определяет свойства «Вид» счёта (Активный/Пассивный) в плане счетов.

9Бухгалтерский учёт: запись движений регистра бухгалтерии

Уровень 1 — база

Как воспользоваться конструктором движений?
Так же, как для регистра накопления: в процедуре ОбработкаПроведения курсор на слово «Движения» → контекстное меню «Конструктор движений…». Выбирается регистр бухгалтерии, настраивается соответствие полей документа полям регистра (счет дебета, счет кредита, субконто, сумма). Конструктор сгенерирует код набора записей с заполнением проводок из данных Шапки/табличных частей и вызовом Движения.Записать().

Уровень 2 — практика

Что такое ручная операция?
Ручная операция — документ (обычно Операция), у которого нет программной логики проведения. Пользователь вручную заполняет бухгалтерскую проводку: счёт дебета, счёт кредита, субконто, суммы. При проведении платформа записывает введённые строки в движения регистра бухгалтерии. Ручные операции нужны для учёта нестандартных ситуаций, исправительных записей, вводных остатков.

Уровень 3 — глубокое понимание

Что такое оперативное и неоперативное проведение? Как отразить движения программно, без проведения документа?
Оперативное проведение — документ проводится в текущем (незакрытом) «окне» оперативного учёта: его движения сразу учитываются в остатках/итогах. Неоперативное проведение — документ вводится «задним числом» (дата раньше границы), для его учёта требуется пересчитать итоги (или он учитывается только в моменте, без пересчёта остатков в реальном времени). Границей управляет обработчик ПолучитьГраницу документа. Это различие критично и для регистра накопления, и для бухгалтерии: неоперативные документы не «портят» текущие остатки мгновенно.
Программная запись движений без проведения документа — сформировать набор записей регистра бухгалтерии напрямую:
НаборЗаписей = РегистрыБухгалтерии.<ИмяРегистра>.СоздатьНаборЗаписей(); НаборЗаписей.Отбор.Регистратор.Установить(СсылкаНаДокумент); НоваяЗапись = НаборЗаписей.Добавить(); НоваяЗапись.Период = ДатаДокумента; НоваяЗапись.СчетДт = ПланыСчетов.Основной.Товары; // счёт дебета НоваяЗапись.СчетКт = ПланыСчетов.Основной.РасчетыСПоставщиками; // счёт кредита НоваяЗапись.Сумма = 1000; // заполнение субконто (по виду субконто): НоваяЗапись.СубконтоДт[ПланыВидовХарактеристик.ВидыСубконто.Материалы] = Материал; НаборЗаписей.Записать();
Такой способ применяется, когда логика проводок строится в отдельном алгоритме, а не через стандартный механизм «Движения» документа. Важно согласовать периоды, виды движения и признак корреспонденции с логикой учёта.

10Бухгалтерский учёт: чтение данных регистра бухгалтерии

Уровень 1 — база

Как обратиться в запросе к физической таблице регистра бухгалтерии? Назовите основные поля.
Физическая таблица движений: РегистрБухгалтерии.<ИмяРегистра>.Движения. Основные поля:
— Ссылка (регистратор), НомерСтроки, Период, ВидДвижения (приход/расход по счёту);
— СчетДт, СчетКт (при ведении корреспонденции) или Счет;
— измерение Субконто1..СубконтоN (значения аналитики);
— ресурсы Сумма, Количество, СуммаВВалюте;
— служебные поля Активность, Регистратор.Номер и т.п.

Уровень 2 — практика

Какие виртуальные таблицы есть у регистра бухгалтерии? Какие параметры в них присутствуют? Как сделать отбор по субконто?
Виртуальные таблицы: Остатки (остатки на дату), Обороты (обороты за период), ОстаткиИОбороты (и то и другое).
Параметры: у остатков — Период, Условие, Граница, МетодДополненияПериодичности, ВключаяОборотыДоПериода, ВключаяОборотыВПериоде, ВестиИтогиПоКорреспонденции(флаг); у оборотов — Периодичность, Период, Условие, Граница. Условие — строка отбора, выполняемая на сервере (обязательная к использованию для скорости).
Отбор по субконто — в параметре Условие через проверку признака ведения:
ВЫБРАТЬ Ост.Счет, Ост.СуммаОстаток ИЗ РегистрБухгалтерии.<ИмяРегистра>.Остатки( &Дата, Субконто1 = &Значение1 И (Субконто2 = &Значение2 ИЛИ НЕ ВЫРАЗИТЬ(Счет.ВестиСубконто2, БУЛЕВО)) ) КАК Ост
Конструкция «ИЛИ НЕ ВестиСубконтоN» гарантирует, что счета, не ведущие это субконто, не потеряются из выборки. Поля субконто в ВТ называются Субконто1, Субконто2…

Уровень 3 — глубокое понимание

Что такое таблица итогов регистра бухгалтерии? Как управлять итогами? Какова структура индекса регистра бухгалтерии?
Таблица итогов — агрегированные данные регистра (остатки и обороты по счетам и периодам), используемые виртуальными таблицами. Управление итогами: настройки регистра — «Ведение итогов» (по счетам/субсчетам, по корреспонденции, по субконто), «Использовать стандартные периоды», возможность пересчитывать итоги регламентным заданием («Пересчёт итогов» в администрировании) после исправлений или неоперативного проведения.
Структура индекса регистра бухгалтерии строится вокруг ключевых полей выборки: Период, Счет (или СчетДт/СчетКт), Субконто1..N. Это обеспечивает быстрые отборы «по счету», «по субконто», «по периоду». Индексы по субконто настраиваются на измерениях (признак «Индексировать»). Правильное сочетание признаков ведения итогов и индексации определяет производительность отчётов по бухгалтерскому учёту.

11Сложные периодические расчёты: основные понятия

Уровень 1 — база

Что такое вид расчёта? Каковы принципы регистрации записей?
Вид расчёта — тип начисления/удержания (оклад, премия, отпуск, аванс). Виды расчётов хранятся в плане видов расчёта, а их результаты — в регистре расчёта в виде записей. Принцип регистрации: каждая запись относится к виду расчёта, сотруднику (измерению) и периоду; чтобы результат попал в расчёт, запись должна быть зарегистрирована в регистре и «действовать» в нужном периоде. Вид расчёта определяет, как запись участвует в вытеснении и в расчёте по базе.

Уровень 2 — практика

Что такое период действия и период регистрации?
Период действия — временной интервал, на который распространяется результат расчёта (например, оклад за январь). Период регистрации — дата, когда запись фактически введена/зарегистрирована в системе (например, запись внесена 10 февраля, но действует с 1 января). Отличие важно для вытеснения и пересчётов: период действия определяет, когда результат «работает», а период регистрации — когда он был зафиксирован (влияет на последовательность пересчёта).

Уровень 3 — глубокое понимание

Что такое зависимость по базовому периоду? Что такое ведущие расчёты и перерасчёт? Что такое сторнирование?
Зависимость по базовому периоду — вид расчёта использует результаты других видов за определённый (базовый) период: например, премия = 10% от оклада за квартал. В плане видов расчёта настраиваются списки «Базовые виды», в регистре расчёта — механизм получения базы (через Виртуальную таблицу или получение данных по базе).
Ведущие расчёты — виды, чьи результаты используются данным видом. Если изменяется запись ведущего вида, зависимые записи должны быть пересчитаны — для этого служит механизм перерасчёта: регистр перерасчётов сохраняет пары «кто изменился → кого пересчитать», а при следующем запуске расчёта помеченные записи пересчитываются. Сторнирование — отмена результата записи путём добавления зеркальной записи с противоположным знаком (отрицательной суммы), чтобы исключить её влияние, не удаляя историю. В 1С это выражается добавлением записи с тем же видом и отрицательным результатом либо специальным признаком.

12Сложные периодические расчёты: планы видов расчёта

Уровень 1 — база

Каково назначение плана видов расчёта?
План видов расчёта — конфигурационный объект, хранящий перечень видов расчёта (оклад, премия, отпуск, удержания…) и их взаимосвязи: какие виды вытесняют друг друга, какие служат базой для других, используется ли период действия. Это «словарь» расчётных правил, к которому обращается регистр расчёта при вычислении.

Уровень 2 — практика

Каковы свойства плана видов расчёта?
План видов расчёта — объект конфигурации, у которого два ключевых свойства:
— «Использует период действия» — включает механизм вытеснения по периоду действия; появляется возможность указать для каждого вида те виды, которые его вытесняют;
— «Зависимость от базы» — включает механизм зависимости по базовому периоду; задаёт, в каком плане видов расчёта находятся базовые виды и как определяется зависимость — по периоду действия или по периоду регистрации.
У самого вида расчёта (элемента плана) есть:
— Код и Наименование (название, которое видит пользователь);
— Базовые виды — виды, чьи результаты используются при расчёте данного вида (например, Оклад — базовый для Премии);
— Вытесняющие виды — виды, которые вытесняют данный вид по периоду действия (например, Невыход вытесняет Оклад);
— Ведущие виды — виды, изменение результатов которых требует перерасчёта данного; все базовые виды входят в ведущие, но ведущими могут быть и другие (для Премии ведущие — Оклад и Невыход);
— признак, в каких единицах измеряется продолжительность записи (дни или часы).

Уровень 3 — глубокое понимание

Какова структура плана видов расчёта? Какие проверки выполняются при записи вида расчёта? Какова структура таблиц БД для плана расчёта?
Структура плана видов расчёта: элементы (виды расчёта), предопределённые элементы, реквизиты и табличные части связей — «Базовые», «Вытесняющие», «Ведущие». На основе объекта конфигурации платформа создаёт в БД таблицу, где хранится информация о видах расчёта и их взаимосвязях.
Проверки при записи вида расчёта:
— уникальность кода и наименования;
— корректность связей: вид не может быть базовым или вытесняющим сам для себя, цепочки связей не должны замыкаться;
— согласованность с настройками плана: если у плана не включены период действия или зависимость от базы, соответствующие связи у видов недоступны.
Пользователь в процессе работы может добавлять новые виды расчёта, но предопределённые виды задаются разработчиком в конфигураторе.
Структура таблиц БД: как у справочника — основная таблица (Код, Наименование и реквизиты) плюс отдельные таблицы для хранения табличных частей связей (Базовые, Вытесняющие, Ведущие).

13Сложные периодические расчёты: регистры расчёта

Уровень 1 — база

Каково назначение регистра расчёта?
Регистр расчёта хранит результаты периодических расчётов: записи «сотрудник + вид расчёта + период + результат + продолжительность». Он обеспечивает учёт вытеснения одних записей другими, получение базы по базовым видам и перерасчёт при изменении ведущих видов. Применяется в зарплатных задачах, тарификации, любых расчётах, где важен период действия и взаимозависимость видов.

Уровень 2 — практика

Каковы свойства и структура регистра расчёта? Какие виртуальные таблицы у него есть?
Свойства и механизмы регистра расчёта:
— измерения (например, Сотрудник) и ресурсы Результат, Продолжительность (дни/часы);
— признаки использования периода действия и периода регистрации;
— связанный план видов расчёта, на основе которого работают механизмы вытеснения и базы;
— связь с графиком (непериодический регистр сведений с данными нормы времени);
— подчинённый объект Перерасчёт — таблица, куда платформа записывает, какие записи следует пересчитать.
Ключевые механизмы: вытеснение по периоду действия (для каждой записи формируется фактический период действия) и зависимость по базовому периоду (два вида: по периоду действия и по периоду регистрации).
Виртуальные таблицы:
— ФактическийПериодДействия — записи с учётом вытеснения: показывает реальные отрезки, в которых запись «работает» (фактический период действия);
— ДанныеГрафика — данные графика (норма и факт дней/часов) для записей;
— Баз<ИмяРегистра> (например, РегистрРасчета.Начисления.БазаНачисления) — данные для расчёта базы зависимых (вторичных) записей;
— хранимые записи читаются из таблиц регистра Записи и Движения (как у всех регистров).
Типовые параметры ВТ: Период, Периодичность, Условие, Граница; у ДанныеГрафика — также ВидГрафика.

Уровень 3 — глубокое понимание

Как устроена технология формирования и расчёта записей регистра расчёта? Что такое перерасчёт записей? Как настроить зависимость по базовому периоду и протяжённые во времени расчёты?
Формирование: записи создаются документами (начисления, отпуска) через набор записей регистра. Расчёт: для каждой записи определяется результат с учётом вытеснения (запись фактически «работает» с учётом перекрывающих её записей) и базы (суммы значений базовых видов за базовый период). Механизм Движения.РегистрРасчета + метод Записать() регистрирует движение; вытеснение учитывается автоматически при обращении к виртуальной таблице ФактическийПериодДействия.
Перерасчёт: если изменилась запись «ведущего» вида, система регистрирует необходимость пересчитать зависимые записи в таблице перерасчётов (объект РегистрыРасчета.Имя.Перерасчет). Записи, попавшие в таблицу перерасчёта, пересчитываются при следующем запуске расчёта. Проверяется через ПолучитьПерерасчет() или запрос к РегистрРасчета.ИмяРасчета.Перерасчет.
Зависимость по базовому периоду: в плане видов расчёта для вида указываются Базовые виды; в регистре расчёта данные базы получают виртуальной таблицей Баз<ИмяРегистра> (например, РегистрРасчета.Начисления.БазаНачисления) с параметрами «измерения основного» и «измерения базового». Есть два вида зависимости: по периоду действия (берутся базовые записи, чей период действия пересекается с базовым периодом) и по периоду регистрации (базовые записи попадают в базовый период значением периода регистрации). База пропорциональна перекрытию периодов и считается с учётом данных графика.
Протяжённые во времени расчёты — использование признака «Использовать период действия»: запись действует с даты начала по дату окончания, поэтому не нужно заводить отдельную запись на каждый день. Продолжительность действия учитывается в днях или часах.

14Универсальные коллекции значений

Уровень 1 — база

Назовите все универсальные коллекции 1С.
Универсальные коллекции значений:
1) Массив — простой набор значений с числовыми индексами;
2) Структура — набор пар «ключ-значение» с именованными ключами;
3) СписокЗначений — упорядоченный список с метками, флагами, представлением;
4) Соответствие — «ассоциативный массив»: пары ключ-значение, ключ — любое значение (не только строка);
5) ТаблицаЗначений — таблица с колонками и строками, типизированными по колонкам;
6) ДеревоЗначений — иерархическая структура с колонками и строками-узлами;
7) ТабличнаяЧасть — часть объекта (документа/справочника), похожа на ТЗ, но связана с объектом;
8) СписокСтруктур (и прочие однотипные менеджеры, напр. СписокСоответствий) — списки вложенных коллекций;
9) Фиксированные массивы (ФиксМассив), ФиксированнаяСтруктура и другие — неизменяемые (fixed) разновидности: быстрее и безопаснее при передаче между вызовами.

Уровень 2 — практика

Где, когда, для чего и как применять ту или иную коллекцию?
— Массив — промежуточные наборы, передача списков в циклы, сортировка через Сортировать();
— Структура — возврат нескольких значений из функции, «параметры запроса», именованные настройки;
— СписокЗначений — выпадающие списки (для выбора), массовые отборы (по ВыбратьЭлемент()), хранение отмеченных элементов;
— Соответствие — быстрый поиск по ключу произвольного типа (по ссылкам, числам), маппинг «ключ → значение»;
— ТаблицаЗначений — табличное представление данных, выгрузка результатов запроса (Выгрузить()), обработка наборов строк;
— ДеревоЗначений — иерархия (группы → элементы), сведение произвольных данных;
— ТабличнаяЧасть — обязательно для табличных частей документов/справочников.
Как: Новый Массив, Новый Структура("К1, К2", Знач1, Знач2), Новый СписокЗначений, Новый Соответствие, Новый ТаблицаЗначений, Новый ДеревоЗначений.

Уровень 3 — глубокое понимание

Каковы методы коллекций значений? Каковы особенности работы с ними?
Общие методы: Количество(), Очистить(), Получить(idx), Установить(idx, знач), Добавить(знач)/Добавить(ключ, знач), Вставить(), Удалить(), Найти(), ЗаполнитьЗначения(), Заполнить(), Скопировать().
— Массив: Добавить(), Вставить(), Удалить(), Найти() (по значению), Сортировать(НаправлениеСортировки); доступ — Массив[индекс];
— Структура: доступ через точку (Структура.Ключ) или Структура["Ключ"], Свойство(), Вставить("Ключ", Знач);
— СписокЗначений: элементы — ЭлементСписка с полями Значение, Представление, Пометка, Метка; методы Добавить(), Вставить(), ВыбратьЭлемент(), ВыгрузитьЗначения(), ЗагрузитьЗначения();
— Соответствие: Вставить(ключ, знач), НайтиПоКлючу(), Удалить(ключ), Количество(); перебор Для Каждого КлючЗначение Из Соответствие Цикл … КонецЦикла;
— ТаблицаЗначений: Колонки.Добавить("Имя", Тип), Добавить() (строка), НайтиСтроки(), Свернуть(), Сортировать(), ВыбратьСтроку(), ЗагрузитьКолонку()/ВыгрузитьКолонку(), индексы Индексы.Добавить();
— ДеревоЗначений: Строки.Добавить(), Строки.Найти(), доступ к подчинённым строки через Строка.Строки.
Особенности работы: ссылочные коллекции передаются «по ссылке» (изменение в функции меняет исходную); фиксированные аналоги (ФиксМассив и др.) неизменяемы и быстрее при частом обращении; при вложении коллекций в параметр запроса имена колонок фиксируются; обход любых коллекций выполняется циклом Для Каждого … Из … Цикл. Скорость поиска: у Соответствия — по ключу O(1), у Массива/СпискаЗначений — линейный перебор; для масс как раз и нужны коллекции, а не циклы по объектам.
