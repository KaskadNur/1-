Циклы
Конструкции для многократного выполнения кода: Для, Для Каждого, Пока, Обход результата запроса.
▼
В 1С доступны три основных цикла: Для (счётчик), Для Каждого (обход коллекции) и Пока (условный). Также часто используется обход выборки запроса. Каждый цикл подходит под свою задачу — счётчик для числовых диапазонов, Для Каждого для коллекций, Пока — когда количество итераций заранее неизвестно.

📊 Виды циклов

ЦиклНазначениеКогда использовать
Для … По … ЦиклСчётчик от начала до концаКогда известно точное число итераций
Для Каждого … Из … ЦиклОбход элементов коллекцииМассивы, таблицы значений, выборки запросов
Пока … ЦиклУсловный циклКогда условие выхода зависит от логики
Пока Выборка.Следующий() ЦиклОбход результата запросаРабота с результатом запроса через объект Выборка

📝 Примеры

// Для — счётчик Для Индекс = 0 По Массив.Количество() - 1 Цикл Сообщить(Массив[Индекс]); КонецЦикла; // Для Каждого — коллекция Для Каждого СтрокаТЗ Из ТаблицаЗначений Цикл Сообщить(СтрокаТЗ.Номенклатура); КонецЦикла; // Пока — условный Пока Выборка.Следующий() Цикл Сообщить(Выборка.Наименование); КонецЦикла; // Прерывание и продолжение Для Каждого Элемент Из Массив Цикл Если Элемент = 0 Тогда Продолжить; // пропустить итерацию КонецЕсли; Если Элемент = 999 Тогда Прервать; // выйти из цикла КонецЕсли; КонецЦикла;
Всегда используйте Для Каждого вместо Для с индексом при обходе коллекций — это безопаснее и читаемее.
🔀
Условия
Ветвление логики через Если / ИначеЕсли / Иначе, а также оператор ?(,,) для кратких условий.
▼
Условный оператор Если позволяет выполнять разный код в зависимости от логического выражения. Поддерживаются вложенные условия, цепочки ИначеЕсли и тернарный оператор ?(,,) для кратких присваиваний. Логические операторы: И, ИЛИ, НЕ.

📊 Конструкции

КонструкцияОписание
Если … Тогда … КонецЕслиПростое условие
Если … Тогда … Иначе … КонецЕслиУсловие с альтернативной веткой
Если … Тогда … ИначеЕсли … Иначе … КонецЕслиЦепочка условий (аналог switch/case)
?(Условие, ЗначениеИстина, ЗначениеЛожь)Тернарный оператор — возвращает одно из двух значений

📝 Примеры

// Полное условие Если Сумма > 1000 Тогда Скидка = 10; ИначеЕсли Сумма > 500 Тогда Скидка = 5; Иначе Скидка = 0; КонецЕсли; // Тернарный оператор Результат = ?(Сумма > 0, Сумма, 0); // Вложенные условия с логическими операторами Если (Сумма > 1000 И Контрагент = "VIP") ИЛИ НЕ ОграничениеСкидки Тогда Скидка = 15; КонецЕсли;
Тернарный оператор ?(,,) удобен для простых присваиваний, но не злоупотребляйте им — сложные вложенные тернарники сильно снижают читаемость кода.
⚙️
Директивы компиляции
Указания, где будет выполняться код: на клиенте, на сервере, на сервере без контекста, на клиенте на сервере без контекста.
▼
Директивы компиляции определяют, на какой стороне (клиент или сервер) будет выполняться процедура или функция. Они обязательны в управляемом приложении и влияют на доступность объектов: на клиенте нельзя работать с базой данных, на сервере — с элементами формы.

📊 Директивы

ДирективаГде выполняетсяЧто доступноКогда использовать
&НаКлиентеТонкий/толстый клиент, вебФормы, элементы управления, диалогиОбработчики команд формы
&НаСервереСервер 1СБаза данных, запросы, объекты конфигурацииЗапись объектов, запросы
&НаСервереБезКонтекстаСервер 1СБаза данных, но нет данных формыУниверсальные функции
&НаКлиентеНаСервереБезКонтекстаИ клиент, и серверТолько встроенные функции и параметрыЧистые функции, валидаторы

📝 Пример

&НаКлиенте Процедура КомандаРассчитать(Команда) Результат = РассчитатьНаСервере(Объект.Сумма); Объект.Итог = Результат; КонецПроцедуры &НаСервереБезКонтекста Функция РассчитатьНаСервере(Сумма) Запрос = Новый Запрос("ВЫБРАТЬ &Сумма * 1.2"); Запрос.УстановитьПараметр("Сумма", Сумма); Возврат Запрос.Выполнить().Выгрузить()[0][0]; КонецФункции
Если метод не использует данные формы — всегда используйте &НаСервереБезКонтекста. Это снижает нагрузку на сервер и позволяет вызывать метод из любого места.
📤
Экспортные методы
Процедуры и функции, доступные для вызова из других модулей — ключевое слово Экспорт открывает метод наружу.
▼
По умолчанию все процедуры и функции в модуле являются приватными — их можно вызвать только внутри того же модуля. Ключевое слово Экспорт делает метод доступным извне. Это основной механизм создания API модулей и повторного использования кода.

📊 Правила видимости

МодификаторВидимостьПример
Без модификатораТолько внутри текущего модуляПроцедура ВнутренняяПроцедура() — локальная
ЭкспортИз любого модуля через точкуФункция РассчитатьСумму() Экспорт — публичная
АсинхДля асинхронных методов на клиентеАсинх Процедура ОткрытьФайл() — не блокирует UI

📝 Пример вызова

// В модуле ОбщегоНазначения Функция ПолучитьТекущуюДатуСеанса() Экспорт Возврат ТекущаяДатаСеанса(); КонецФункции // Вызов из другого модуля Дата = ОбщегоНазначения.ПолучитьТекущуюДатуСеанса();
Правило хорошего тона: экспортируйте только те методы, которые действительно нужны снаружи. Всё остальное оставляйте приватным — это защищает от случайного использования внутренней логики.
📦 Модули
📑
Виды модулей
Каждый объект 1С имеет свои модули: модуль объекта, менеджера, формы, команды, общий модуль, модуль сеанса, модуль приложения.
▼
В 1С существует множество типов модулей, каждый со своим контекстом выполнения. Модуль объекта — код экземпляра справочника или документа. Модуль менеджера — код типа объекта (как класс в ООП). Модуль формы — обработчики событий интерфейса. Общие модули — глобальные библиотеки. Модуль сеанса — инициализация при старте.

📊 Все виды модулей

МодульПринадлежностьНазначениеКонтекст
Модуль объектаСправочник, Документ, Регистр и др.События экземпляра (ПередЗаписью, ПриЗаписи, ОбработкаПроведения)Сервер
Модуль менеджераСправочник, Документ, Регистр и др.Статические методы типа (создание, поиск, шаблоны)Сервер
Модуль формыКаждая форма объектаОбработчики команд, события элементов формыКлиент + Сервер
Модуль командыКоманда формыКод выполнения командыКлиент + Сервер
Общий модульГлобальныйПовторно используемые функцииКлиент / Сервер / Внешнее соединение
Модуль сеансаГлобальныйУстановка параметров сеанса при подключенииСервер
Модуль приложенияГлобальныйОбработчики старта/завершения приложенияКлиент
Модуль внешнего соединенияГлобальныйКод при COM-соединенииВнешнее соединение
Модуль менеджера — это «класс» в терминах ООП, а модуль объекта — «экземпляр». В менеджере нет данных конкретного элемента, зато есть методы для работы с типом в целом.
🏗️
Типовая структура модуля
Рекомендуемый порядок: переменные, экспортные методы, события объекта, служебные процедуры, инициализация.
▼
Хорошо структурированный модуль читается сверху вниз как книга: сначала объявления, потом публичный API, затем обработчики событий, в конце — внутренняя кухня. Это стандарт, принятый в типовых конфигурациях и описанный в стандартах 1С:ИТС. Соблюдение структуры критично при командной разработке.

📊 Рекомендуемый порядок

БлокЧто содержитПримеры
1. ПеременныеГлобальные переменные модуля (редко используются)Перем мКэш;
2. Программный интерфейсЭкспортные процедуры и функции — публичное APIФункция Рассчитать() Экспорт
3. Обработчики событийПроцедуры-обработчики (ПередЗаписью, ПриСозданииНаСервере)Процедура ПередЗаписью(Отказ)
4. Служебные процедурыВнутренние (не экспортные) вспомогательные методыПроцедура ЗаполнитьТаблицу()
5. ИнициализацияКод, выполняемый при загрузке модулямКэш = Новый Соответствие;

📝 Пример структуры

#Область ПрограммныйИнтерфейс Функция ПолучитьДанные() Экспорт // Публичный метод КонецФункции #КонецОбласти #Область ОбработчикиСобытий Процедура ПередЗаписью(Отказ) // Событие объекта КонецПроцедуры #КонецОбласти #Область СлужебныеПроцедурыИФункции Процедура ВнутренняяПроцедура() // Приватный метод КонецПроцедуры #КонецОбласти
Используйте директивы препроцессора #Область / #КонецОбласти для группировки кода — это позволяет сворачивать блоки в редакторе и делает модуль читаемым даже при 1000+ строк.
⚡
Модуль объекта vs Модуль менеджера
Модуль объекта — события конкретного экземпляра (ПередЗаписью). Модуль менеджера — статические методы типа (создание, поиск, заполнение).
▼
Модуль объекта привязан к конкретному экземпляру справочника или документа — в нём доступны реквизиты этого элемента, и срабатывают события жизненного цикла (перед записью, при проведении). Модуль менеджера работает на уровне типа — в нём нет данных конкретного элемента, но есть методы для создания, поиска, получения форм и шаблонов.

📊 Сравнение

ПараметрМодуль объектаМодуль менеджера
КонтекстКонкретный экземпляр (СправочникОбъект.Номенклатура)Тип в целом (Справочники.Номенклатура)
Доступ к реквизитамДа — через точку (ЭтотОбъект.Наименование)Нет — нет конкретного элемента
СобытияПередЗаписью, ПриЗаписи, ОбработкаПроведения, ПередУдалениемНет событий жизненного цикла
Типичные задачиВалидация данных, заполнение по умолчанию, проведениеСоздание элемента, поиск, получение макета, формы
ВызовАвтоматически при операциях с объектомЧерез менеджер: Справочники.Номенклатура.Метод()

📝 Примеры

// МОДУЛЬ ОБЪЕКТА — событие конкретного элемента Процедура ПередЗаписью(Отказ) Если ПустаяСтрока(Наименование) Тогда Сообщить("Наименование не заполнено!"); Отказ = Истина; КонецЕсли; КонецПроцедуры // МОДУЛЬ МЕНЕДЖЕРА — метод для всех элементов Функция СоздатьНоменклатуру(Наименование) Экспорт НовыйЭлемент = СоздатьЭлемент(); НовыйЭлемент.Наименование = Наименование; НовыйЭлемент.Записать(); Возврат НовыйЭлемент.Ссылка; КонецФункции // Вызов извне Ссылка = Справочники.Номенклатура.СоздатьНоменклатуру("Новый товар");
Запомни: Объект = экземпляр (this), Менеджер = класс (static). В модуле менеджера нельзя написать «ЭтотОбъект.Наименование», потому что нет конкретного «этого».

Общие модули
Глобальные библиотеки с повторно используемыми процедурами, доступными из любого места конфигурации с настройкой контекста.
▼
Общие модули хранят универсальные алгоритмы и утилитарные функции, вызываемые из разных объектов. Они поддерживают свойства: сервер, клиент, внешнее соединение, повторное использование возвращаемых значений, привилегированный режим. Правильное разделение кода по общим модулям — основа чистой архитектуры.

📝 Примеры именования

// Клиентские модули ОбщегоНазначенияКлиент // Клиентские утилиты ОбщегоНазначенияКлиентСервер // Общий код для клиента и сервера // Серверные модули ОбщегоНазначения // Серверные утилиты РаботаСДанными // Работа с таблицами, запросами Интеграция // Обмен с внешними системами // Повторное использование ОбщегоНазначенияПовтИсп // Кэшируемые функции
Разделяйте клиент и сервер. Никогда не выполняйте запросы к БД на клиенте — это приведёт к ошибке. Используйте директивы &НаКлиенте, &НаСервере, &НаСервереБезКонтекста.
🗂️ Универсальные коллекции значений
📚
Универсальные коллекции значений
Встроенные объекты языка 1С для хранения и обработки данных в памяти: массив, структура, соответствие, список значений, таблица значений, дерево значений.
▼
Коллекции — это объекты встроенного языка 1С, позволяющие временно хранить и обрабатывать данные без записи в базу. Каждая коллекция имеет своё назначение: массив — упорядоченный список, структура — именованные пары ключ-значение, соответствие — ассоциативный массив, таблица значений — двумерная таблица в памяти. Они не сохраняются в базе данных и существуют только во время выполнения кода.

📊 Основные коллекции

КоллекцияНазначениеОсобенности

СтруктураИменованные пары «ключ — значение»Ключ — строка, доступ через точку (Структура.Ключ), удобна для параметров
СоответствиеАссоциативный массивКлюч — любой тип, быстрый поиск по хешу, аналог Map/Dictionary
СписокЗначенийСписок с дополнительными свойствамиЭлементы имеют Представление, Пометка, Картинка; удобен для выбора пользователем
ТаблицаЗначенийДвумерная таблица в памятиИмеет колонки и строки, поддерживает сортировку, поиск, группировку; аналог DataTable
ДеревоЗначенийИерархическая структура данныхСтроки могут содержать подчинённые строки; используется для многоуровневых отчётов
СтрокаТаблицыЗначенийОдна строка таблицы значенийДоступ к колонкам через точку; методы ВыбратьСтроку(), Получить()

🏛️ Объекты конфигурации
🧩
Объекты конфигурации
Общие объекты (роли, подсистемы), прикладные (справочники, документы, регистры) и подчинённые (реквизиты, формы, макеты).
▼
Все элементы конфигурации 1С делятся на три уровня. Общие объекты определяют инфраструктуру: роли, подсистемы, общие модули, интерфейсы. Прикладные объекты — это бизнес-сущности: справочники, документы, регистры, планы счетов. Подчинённые объекты — составные части прикладных: реквизиты, табличные части, формы, макеты, команды.

Константы
Хранение единичных значений на уровне информационной базы: название организации, валюта учёта, адрес, флаги включения функциональности.
▼
Константы предназначены для хранения одного значения на всю базу данных — например, название организации, валюта регламентированного учёта или адрес сервера. Они не имеют истории изменений (если не используется механизм истории) и доступны из любого места конфигурации. Часто используются как переключатели функциональности (включить/выключить учёт по складам).

Справочники
Нормативно-справочная информация: номенклатура, контрагенты, сотрудники. Поддерживают иерархию, подчинённость, предопределённые элементы.
▼
Справочники — основной объект для хранения условно-постоянной информации. Они поддерживают иерархию (группы и элементы), подчинённость (один справочник подчинён другому — например, договоры контрагентов) и предопределённые элементы (заданные в конфигураторе, неудаляемые). Каждый справочник имеет стандартные реквизиты: Код, Наименование, Родитель, Владелец.

Документы
Объекты, фиксирующие хозяйственные операции: поступление, реализация, начисление. Поддерживают проведение, ввод на основании, нумерацию.
▼
Документы — центральный объект учёта в 1С. Каждый документ имеет дату, номер, ссылку и может содержать табличные части. Главная особенность — проведение: при проведении документ создаёт движения по регистрам (накопления, бухгалтерии, расчёта). Документы поддерживают ввод на основании, нумераторы и могут быть регистраторами.

Журналы документов
Объединённый список документов разных типов для удобного просмотра: общий журнал, рабочий журнал, журналы по подсистемам.
▼
Журнал документов — это не хранилище, а представление, объединяющее несколько типов документов в одном списке. Он не содержит собственных данных, а только отображает документы с общими графами (Дата, Номер, Контрагент). Позволяет пользователю видеть все операции в одном окне вместо перехода между разными документами.

Формы
Интерфейсные объекты для ввода, отображения и редактирования данных. Управляемые и обычные формы, модальные и немодальные.
▼
Формы — это интерфейсные объекты, через которые пользователь взаимодействует с данными. В современных конфигурациях используются управляемые формы (разделяют клиент и сервер, строятся декларативно). Формы имеют модули с обработчиками событий (ПриСозданииНаСервере, ПриОткрытии, ОбработкаВыбора). Каждый объект может иметь несколько форм: форма элемента, списка, выбора.

Форма спискаПросмотр списка элементов с отборами и сортировкой
Форма выбораМодальное или немодальное окно для выбора значения из списка
Форма группыРедактирование группы в иерархическом справочнике
Общая формаУниверсальная форма, не привязанная к конкретному объекту

Управляемые формы работают по принципу «тонкий клиент» — вся тяжёлая логика (запросы, запись) выполняется на сервере, а на клиенте только отображение и реакция на действия пользователя.
📁 Регистры
📋
Регистр сведений (виды)
Периодические, независимые и подчинённые регистратору. Периодичность, срез последних, режимы записи.
▼
Регистр сведений имеет три ключевых различия. Периодичность: периодический регистр хранит значения с привязкой к дате (курсы валют), непериодический — без даты (штрихкоды). Режим записи: независимый записывается вручную или программно, подчинённый регистратору — только документом. Периодический срез позволяет получить актуальное значение на любую дату.

Регистр накоплений
Хранит количественные движения ресурсов (товары, деньги) с возможностью получения остатков и оборотов на любую дату.
▼
Регистр накоплений фиксирует изменения количественных показателей: приход и расход товаров, денежных средств, материалов. Он всегда подчинён регистратору (документу) и позволяет получать остатки и обороты в разрезе измерений. Существуют два вида: остатки (учитывают приход/расход) и обороты (только обороты без остатков).

📊 Структура и параметры

ПараметрОписание
НазначениеУчёт движения материальных и денежных ресурсов
ВидыОстатки (приход/расход → можно получить остаток) / Обороты (только обороты, без остатков)
Режим записиТолько подчинённый регистратору (документу)
СтруктураИзмерения + Ресурсы (числовые) + Реквизиты
Виды движенийПриход (+) / Расход (−)
ЗапросыОстатки, Обороты, ОстаткиИОбороты

Ключевое отличие: Работает с количественными/суммовыми показателями, поддерживает приход/расход и расчёт остатков. Всегда привязан к документу-движению.
⚖️
Регистр бухгалтерии
Специализированный регистр для ведения бухгалтерского учёта по плану счетов с поддержкой двойной записи, субконто и корреспонденции счетов.
▼
Регистр бухгалтерии реализует классический бухгалтерский учёт: каждая запись содержит дебет и кредит (корреспонденцию счетов), сумму и количество. Он работает на основе плана счетов, поддерживает субконто (аналитику) и многоуровневую иерархию счетов. В отличие от регистра накоплений, здесь обязательна двойная запись — каждое движение отражается одновременно по дебету одного счёта и кредиту другого.

Ключевое отличие: Единственный регистр с корреспонденцией (двойная запись Дт/Кт), работает через план счетов и субконто. Не заменяет регистр накоплений — это отдельная бухгалтерская модель.

Регистр расчёта
Хранит результаты сложных периодических расчётов (зарплата, налоги, отпуска) с поддержкой зависимостей между записями и механизмом перерасчётов.
▼
Регистр расчёта предназначен для задач расчёта по периодам, где результат одной записи зависит от других — например, зарплата, больничные, отпускные. Он привязан к периоду действия (а не только периоду регистрации) и поддерживает виды расчёта с формулами и базовыми видами расчёта. Если изменяются исходные данные (например, оклад), система автоматически определяет, какие записи нужно пересчитать.

📊 Структура и параметры

ПараметрОписание
НазначениеСложные периодические расчёты с взаимозависимыми видами начислений
ОсноваПлан видов расчёта (формулы, базовые виды, ведущие виды, вытесняющие виды)
ПериодыПериод регистрации (когда записано) + Период действия (за какой период действует)
ЗависимостиБазовые виды → от чего зависит расчёт; Ведущие → что влияет на перерасчёт; Вытесняющие → что прерывает действие (например, больничный вытесняет оклад)
ПерерасчётАвтоматическое определение записей, требующих пересчёта при изменении исходных данных
СтруктураИзмерения (сотрудник, организация) + Ресурсы (результат, отработано дней/часов) + Реквизиты
ПримерыНачисление зарплаты, отпускных, больничных, премий, налогов, удержаний
Ключевое отличие: Уникальный механизм периода действия, видов расчёта с формулами и перерасчётов. Предназначен именно для расчётных задач, где записи зависят друг от друга во времени.

Функциональные опции
Механизм включения/отключения функциональности конфигурации: многоскладской учёт, валютный учёт, работа с НДС — всё управляется константами-функциональными опциями.
▼
Функциональные опции позволяют включать и отключать целые блоки функциональности конфигурации. Они основаны на константах или регистрах сведений и влияют на видимость элементов интерфейса, доступность команд и состав отчётов. Это мощный инструмент для адаптации типовой конфигурации под нужды конкретного предприятия без изменения кода.

Функциональные опции — это не просто флаги. Они глубоко интегрированы в платформу: при отключении опции платформа автоматически скрывает связанные с ней элементы интерфейса и оптимизирует запросы.
📐
Планы видов характеристик
Механизм для создания произвольных свойств (характеристик) объектов без изменения конфигурации: цвет, размер, материал для номенклатуры.
▼
План видов характеристик (ПВХ) — это справочник, который определяет, какие дополнительные свойства может иметь объект. Например, для номенклатуры это могут быть цвет, размер, вес. Сами значения хранятся в регистре сведений «Значения свойств объектов». ПВХ позволяет пользователю самостоятельно добавлять новые характеристики без участия программиста.

📊 Структура механизма

КомпонентНазначение
План видов характеристикСправочник, описывающий доступные свойства (Цвет, Размер, Вес)
Тип значения характеристикОпределяет, какой тип данных может храниться (число, строка, ссылка, булево)
Дополнительные значенияСправочник конкретных значений характеристик (Красный, XL, 10 кг)
Регистр сведенийХранит связь: Объект + Характеристика + Значение

📝 Пример

// Получение характеристик номенклатуры Запрос = Новый Запрос( "ВЫБРАТЬ | Значения.Свойство, | Значения.Значение |ИЗ | РегистрСведений.ДополнительныеСведения КАК Значения |ГДЕ | Значения.Объект = &Номенклатура");
ПВХ — мощный механизм расширяемости. Он позволяет пользователю добавлять поля к справочникам без изменения структуры конфигурации. Используется в УТ, ERP, КА для гибкой настройки под предприятие.
🔍 Запросы и оптимизация
🔍
Запросы
Средство языка 1С для извлечения и обработки данных из базы с помощью декларативного SQL-подобного синтаксиса, адаптированного под метаданные.
▼
Запросы в 1С используют собственный язык, похожий на SQL, но адаптированный под метаданные конфигурации. Они позволяют выбирать, группировать, соединять и агрегировать данные из таблиц базы. Запросы выполняются на сервере и возвращают результат в виде таблицы значений или выборки, что делает их основным инструментом для работы с большими объёмами данных.

📊 Ключевые конструкции

КонструкцияНазначение
ВЫБРАТЬОпределяет список полей результата. ВЫБРАТЬ ПЕРВЫЕ N — ограничение количества строк
ИЗИсточник данных — таблица справочника, документа, регистра, виртуальная таблица
ГДЕФильтрация строк по условиям. Не используйте функции в условиях — индексы не работают
СОЕДИНЕНИЕВнутреннее (ТОЛЬКО), ЛЕВОЕ, ПРАВОЕ, ПОЛНОЕ — объединение таблиц
ГРУППИРОВАТЬ ПОГруппировка строк для агрегатных функций (СУММА, КОЛИЧЕСТВО, МАКСИМУМ, МИНИМУМ, СРЕДНЕЕ)
УПОРЯДОЧИТЬ ПОСортировка результата. Лучше сортировать на клиенте, если данных мало
ИТОГИПостроение иерархического результата (для отчётов, аналог GROUP BY ROLLUP)

📝 Пример запроса

ВЫБРАТЬ Номенклатура.Ссылка КАК Номенклатура, Номенклатура.Артикул, Цены.Цена ИЗ Справочник.Номенклатура КАК Номенклатура ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.ЦеныНоменклатуры.СрезПоследних() КАК Цены ПО Номенклатура.Ссылка = Цены.Номенклатура ГДЕ Номенклатура.ЭтоГруппа = ЛОЖЬ УПОРЯДОЧИТЬ ПО Номенклатура.Наименование
Виртуальные таблицы регистров (Остатки, Обороты, СрезПоследних) — это уже готовые оптимизированные представления. Всегда используйте их вместо ручного соединения с регистром.
⚡
Методы оптимизации запросов
Приёмы ускорения выполнения запросов: индексы, виртуальные таблицы с параметрами, ограничение полей, временные таблицы, пакетные запросы.
▼
Оптимизация запросов в 1С начинается с правильного использования виртуальных таблиц с параметрами, выборки только нужных полей и применения индексов. Временные таблицы разбивают сложные запросы на этапы, а пакетные запросы выполняют несколько операций за одно обращение к СУБД. Избегайте соединений с вложенными запросами и функций в условиях — они блокируют использование индексов.

📊 Топ-10 методов оптимизации

МетодОписаниеПример / Правило
1. Виртуальные таблицы с параметрамиПередавайте условия в параметры виртуальной таблицы, а не в ГДЕОстатки(&Период, Номенклатура = &Ном) — вместо фильтра в ГДЕ
2. Только нужные поляНе выбирайте «*» — указывайте конкретные поляВЫБРАТЬ Ссылка, Наименование — вместо ВЫБРАТЬ *
3. Временные таблицыРазбивайте сложные запросы на этапы через ПОМЕСТИТЬУменьшает размер соединений и повышает читаемость
4. Пакетные запросыНесколько запросов в одном пакете — одно обращение к СУБДРазделитель «;» между запросами
5. Без функций в ГДЕФункции (НАЧАЛОПЕРИОДА, ПОДСТРОКА) в условиях отключают индексыФильтруйте по исходному полю, а не по результату функции
6. Правильное соединениеЛЕВОЕ СОЕДИНЕНИЕ быстрее ПОЛНОГО; избегайте вложенных запросов в соединенияхЗаменяйте вложенные запросы на временные таблицы
7. ИндексыИндексируйте часто используемые поля в регистрах и справочникахИзмерения регистров автоматически индексируются
8. РАЗРЕШЕННЫЕЕсли не нужны ограничения RLS — используйте РАЗРЕШЕННЫЕУскоряет за счёт пропуска проверки прав на уровне записей
9. ПЕРВЫЕ NОграничивайте выборку, если нужна только часть данныхВЫБРАТЬ ПЕРВЫЕ 100
10. План запросаАнализируйте план выполнения в консоли запросовИщите Table Scan — это медленное полное сканирование таблицы

📝 Пример: плохо vs хорошо

// ❌ ПЛОХО — функция в условии, нет индекса ВЫБРАТЬ * ИЗ Документ.Реализация ГДЕ НАЧАЛОПЕРИОДА(Дата, МЕСЯЦ) = &НачалоМесяца // ✅ ХОРОШО — диапазон дат, индекс работает ВЫБРАТЬ Ссылка, Номер, Дата ИЗ Документ.Реализация ГДЕ Дата МЕЖДУ &НачалоМесяца И &КонецМесяца
Главное правило: чем меньше данных читает запрос, тем быстрее он работает. Фильтруйте как можно раньше — в параметрах виртуальных таблиц, а не в конце запроса.
