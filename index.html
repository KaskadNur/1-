ЯЗЫК И СИНТАКСИС
🔄
Циклы
Для, Для Каждого, Пока — три основных цикла + обход выборки запроса.
▼
Для — счётчик с известным числом итераций. Для Каждого — обход коллекций (массив, ТЗ, выборка). Пока — условный цикл. Пока Выборка.Следующий() — обход результата запроса. Есть Продолжить (пропустить итерацию) и Прервать (выйти).
Для Индекс = 0 По Массив.Количество() - 1 Цикл Сообщить(Массив[Индекс]); КонецЦикла; Для Каждого СтрокаТЗ Из ТаблицаЗначений Цикл Сообщить(СтрокаТЗ.Номенклатура); КонецЦикла; Пока Выборка.Следующий() Цикл Сообщить(Выборка.Наименование); КонецЦикла;
Всегда используй Для Каждого вместо Для с индексом при обходе коллекций — безопаснее и читаемее.
🔀
Условия
Если / ИначеЕсли / Иначе + тернарный оператор ?(,,).
▼
Если … Тогда … ИначеЕсли … Иначе … КонецЕсли — полная цепочка условий. ?(Условие, Истина, Ложь) — тернарный оператор для кратких присваиваний. Логические операторы: И, ИЛИ, НЕ.
Если Сумма > 1000 Тогда Скидка = 10; ИначеЕсли Сумма > 500 Тогда Скидка = 5; Иначе Скидка = 0; КонецЕсли; Результат = ?(Сумма > 0, Сумма, 0);
Не злоупотребляй тернарником — сложные вложенные ?(,,) снижают читаемость.

Директивы компиляции
&НаКлиенте, &НаСервере, &НаСервереБезКонтекста, &НаКлиентеНаСервереБезКонтекста.
▼
Директивы определяют, где выполняется код. &НаКлиенте — формы, диалоги. &НаСервере — БД, запросы. &НаСервереБезКонтекста — универсальные функции без данных формы (предпочтительнее). &НаКлиентеНаСервереБезКонтекста — чистые функции, валидаторы.
ДирективаГдеДоступно
&НаКлиентеКлиентФормы, элементы, диалоги
&НаСервереСерверБД, запросы, объекты
&НаСервереБезКонтекстаСерверБД, но без данных формы
&НаКлиентеНаСервереБезКонтекстаОбаТолько встроенные функции
Если метод не использует данные формы — всегда &НаСервереБезКонтекста. Это снижает нагрузку и позволяет вызывать из любого места.

Экспортные методы
Ключевое слово Экспорт делает метод доступным из других модулей.
▼
По умолчанию методы приватные (видны только в модуле). Экспорт открывает метод наружу. Асинх — для асинхронных методов на клиенте (не блокирует UI).
// Публичный метод Функция ПолучитьДату() Экспорт Возврат ТекущаяДатаСеанса(); КонецФункции // Вызов из другого модуля Дата = ОбщегоНазначения.ПолучитьДату();
Экспортируй только то, что нужно снаружи. Всё остальное — приватное.

Виды модулей
Объект, менеджер, форма, команда, общий, сеанса, приложения, внешнего соединения.
▼
Модуль объекта — события экземпляра (ПередЗаписью). Модуль менеджера — статические методы типа (создание, поиск). Модуль формы — обработчики UI. Общий модуль — глобальные библиотеки. Модуль сеанса — инициализация при старте.
МодульКонтекстНазначение
ОбъектаСерверПередЗаписью, ПриЗаписи, ОбработкаПроведения
МенеджераСерверСоздатьЭлемент(), НайтиПоНаименованию()
ФормыКлиент+СерверПриСозданииНаСервере, ОбработкаВыбора
КомандыКлиент+СерверКод выполнения команды
ОбщийРазныйПовторно используемые функции
СеансаСерверУстановка параметров сеанса
ПриложенияКлиентСтарт/завершение приложения
Менеджер = класс (static), Объект = экземпляр (this). В менеджере нет ЭтотОбъект.

Типовая структура модуля
Стандартный порядок: переменные → экспорт → события → служебные → инициализация.
▼
Типовая структура модуля: 1) Переменные, 2) Программный интерфейс (экспорт), 3) Обработчики событий, 4) Служебные процедуры, 5) Инициализация. Используй #Область для группировки.
#Область ПрограммныйИнтерфейс Функция ПолучитьДанные() Экспорт // Публичный метод КонецФункции #КонецОбласти #Область ОбработчикиСобытий Процедура ПередЗаписью(Отказ) // Событие объекта КонецПроцедуры #КонецОбласти #Область СлужебныеПроцедурыИФункции Процедура ВнутренняяПроцедура() // Приватный метод КонецПроцедуры #КонецОбласти
#Область позволяет сворачивать блоки в редакторе. Критично при 1000+ строк.

Модуль объекта и Модуль менеджера
Объект = экземпляр (this), Менеджер = класс (static).
▼
Модуль объекта — доступны реквизиты конкретного элемента, события жизненного цикла. Модуль менеджера — нет данных элемента, но есть методы создания, поиска, получения форм.
ПараметрОбъектМенеджер
КонтекстСправочникОбъект.НоменклатураСправочники.Номенклатура
РеквизитыДа — ЭтотОбъект.НаименованиеНет
СобытияПередЗаписью, ПриЗаписиНет
ЗадачиВалидация, заполнениеСоздание, поиск, макеты
ВызовАвтоматическиСправочники.Ном.Метод()
В менеджере нельзя написать ЭтотОбъект.Наименование — нет конкретного «этого».

Общие модули
Глобальные библиотеки с настройкой контекста: клиент, сервер, повторное использование, привилегированный.
▼
Общие модули хранят универсальные функции. Свойства: Клиент (UI), Сервер (БД), Повторное использование (кэш), Привилегированный (без RLS), Внешнее соединение (COM).
СвойствоОписание
КлиентКод на стороне клиента (формы, диалоги)
СерверКод на сервере (запросы, БД)
Повторное использованиеКэширует результат на время вызова/сеанса
ПривилегированныйБез проверки прав (RLS)
Внешнее соединениеДоступен при COM-соединении
// Именование ОбщегоНазначенияКлиент // Клиент ОбщегоНазначенияКлиентСервер // Оба ОбщегоНазначения // Сервер ОбщегоНазначенияПовтИсп // Кэш
Никогда не выполняй запросы на клиенте — ошибка. Разделяй клиент и сервер чётко.

Универсальные коллекции значений
Массив, Структура, Соответствие, СписокЗначений, ТаблицаЗначений, ДеревоЗначений.
▼
Коллекции хранят данные в памяти, не сохраняются в БД. Массив — список по индексу. Структура — ключ-значение (строка). Соответствие — ассоциативный массив (любой ключ). ТЗ — двумерная таблица. Дерево — иерархия.
КоллекцияДоступКлючИерархия
МассивПо индексуЧисло✕
СтруктураПо имениСтрока✕
СоответствиеПо любому ключуЛюбой✕
СписокЗначенийПо индексу—✕
ТаблицаЗначенийПо колонке/строке—✕
ДеревоЗначенийПо уровню—✓
Массив = Новый Массив; Массив.Добавить("A"); Структура = Новый Структура("Ключ1,Ключ2", 10, "V"); Соответствие = Новый Соответствие; Соответствие.Вставить(Ссылка, "Данные"); ТЗ = Новый ТаблицаЗначений; ТЗ.Колонки.Добавить("Имя"); Стр = ТЗ.Добавить(); Стр.Имя = "Иван";
Коллекции живут только в памяти. Для передачи между сеансами — сериализация (XML/JSON).

Режимы работы 1С:Предприятие
Файловый и клиент-серверный режимы: архитектура, отличия, когда какой выбирать.
▼
Файловый режим — БД в файле (1Cv8.1CD), всё на одном компьютере. Простой, но медленный при >5 пользователей. Клиент-серверный — СУБД (MS SQL, PostgreSQL) + сервер 1С, масштабируемый, надёжный, требует лицензий.
ПараметрФайловыйКлиент-серверный
Хранение данныхФайл 1Cv8.1CDСУБД (MS SQL, PostgreSQL)
Количество пользователейДо 5-10До тысяч
СкоростьМедленнее при нагрузкеВысокая
НадёжностьРиск повреждения файлаРезервное копирование, кластер
ЛицензииТолько клиентские+ лицензия на сервер 1С
Управляемое приложениеРаботаетРаботает
// Проверка режима в коде Если ИнформационнаяБаза.Файловая Тогда // Файловый режим Иначе // Клиент-серверный КонецЕсли;
Для разработки используй файловый режим. Для промышленной эксплуатации — только клиент-серверный.

Объекты конфигурации
🧩
ИЕРАРХИЯ ОБЪЕКТОВ
Общие (роли, подсистемы), Прикладные (справочники, документы), Подчинённые (реквизиты, формы).
▼
Общие — инфраструктура: роли, подсистемы, модули, планы обмена. Прикладные — бизнес-сущности: справочники, документы, регистры, перечисления. Подчинённые — реквизиты, табличные части, формы, макеты.
КатегорияПримеры
ОбщиеРоли, Подсистемы, Общие модули, Планы обмена, Web/HTTP-сервисы
ПрикладныеСправочники, Документы, Регистры, ПВХ, Планы счетов, Перечисления, Константы
ПодчинённыеРеквизиты, Табличные части, Формы, Макеты, Команды, Движения
Прикладные — то, что видит пользователь. Общие — работают «под капотом».
🔒
Константы
Единичные значения на уровне ИБ: валюта, адрес, флаги функциональности.
▼
Константы хранят одно значение на всю базу. Доступ: Константы.Имя.Получить() / Установить(). Можно использовать в запросах как Константа.Имя.
Валюта = Константы.ВалютаУчета.Получить(); Константы.АдресСервера.Установить("192.168.1.1"); // В запросе ВЫБРАТЬ Значение ИЗ Константа.ВалютаУчета
Не храни списки или часто меняющиеся данные — для этого регистры сведений.
📁
Справочники
Иерархия (3 вида), подчинённость, предопределённые элементы, код/наименование/владелец/родитель.
▼
Справочники — условно-постоянная информация. Иерархия: без, группы+элементы, элементы. Подчинённость: один подчинён другому (Договоры → Контрагенты). Предопределённые — созданы в конфигураторе, неудаляемы (Справочники.Валюты.Рубль).
Вид иерархииПример
Без иерархииВалюты, Страны
Группы и элементыНоменклатура, Контрагенты
ЭлементыПодразделения
// Создание НовыйЭлемент = Справочники.Номенклатура.СоздатьЭлемент(); НовыйЭлемент.Наименование = "Товар"; НовыйЭлемент.Родитель = Справочники.Номенклатура.Группа; НовыйЭлемент.Записать(); // Предопределённый Валюта = Справочники.Валюты.Рубль; // Проверка на группу Если Ссылка.ЭтоГруппа Тогда ... КонецЕсли;
Предопределённые — надёжная «точка опоры» в коде. Имя не меняется.
📄
Документы
Проведение, ввод на основании, регистратор, нумераторы, движения по регистрам.
▼
Документы фиксируют хозяйственные операции. Имеют дату, номер, табличные части. Проведение — формирует движения по регистрам. Ввод на основании — создаёт из другого документа. Регистратор — документ, который пишет в регистр.
МеханизмОписание
ПроведениеОбработкаПроведения — формирует движения по регистрам
Ввод на основанииОбработкаЗаполнения — заполняет из другого документа
РегистраторДокумент создаёт движения в регистре
НумераторПериодичность: год, квартал, месяц, бессрочно
Процедура ОбработкаПроведения(Отказ, Режим) Движения.ТоварыНаСкладах.Записывать = Истина; Для Каждого Стр Из Товары Цикл Дв = Движения.ТоварыНаСкладах.Добавить(); Дв.ВидДвижения = ВидДвиженияНакопления.Приход; Дв.Номенклатура = Стр.Номенклатура; Дв.Количество = Стр.Количество; КонецЦикла; КонецПроцедуры;
Непроведённый документ хранится, но не влияет на остатки.
📰
Журналы документов
Представление (view), объединяющее несколько типов документов в одном списке.
▼
Журнал — это не хранилище, а представление над таблицами документов. Содержит общие графы (Дата, Номер, Контрагент). Документ автоматически попадает в журнал, если включён в его состав.
Журнал не создаёт отдельную таблицу в БД. Это динамический список для удобного просмотра.
🖥️
Формы
Управляемые формы: модуль формы, события, виды (объекта, списка, выбора, общая).
▼
Формы — интерфейс пользователя. Управляемые формы разделяют клиент и сервер. Ключевые события: ПриСозданииНаСервере (инициализация), ПриОткрытии (клиент), ПередЗаписьюНаСервере, ОбработкаВыбора.
СобытиеКонтекстКогда
ПриСозданииНаСервереСерверПеред отображением формы
ПриОткрытииКлиентФорма уже видна
ПередЗаписьюНаСервереСерверПеред записью объекта
ПослеЗаписиНаСервереСерверПосле успешной записи
ОбработкаВыбораКлиентПередано значение из др. формы
Управляемые формы: тяжёлая логика на сервере, на клиенте — только отображение.

Функциональные опции
Включение/отключение блоков функциональности: многоскладской учёт, валютный учёт, НДС.
▼
Функциональные опции управляют видимостью элементов интерфейса и доступностью команд. Хранятся в константах или регистрах сведений. Проверка: ПолучитьФункциональнуюОпцию("Имя").
Если ПолучитьФункциональнуюОпцию("ИспользоватьНДС") Тогда // Показываем колонку НДС КонецЕсли; // В запросе ВЫБРАТЬ ... ГДЕ &ИспользоватьНДС = ИСТИНА
При отключении опции платформа автоматически скрывает связанные элементы и оптимизирует запросы.

Планы видов характеристик (ПВХ)
Произвольные свойства объектов без изменения конфигурации: цвет, размер, материал.
▼
ПВХ определяет, какие свойства может иметь объект. Значения хранятся в регистре сведений «Дополнительные сведения». Пользователь сам добавляет характеристики без программиста.
КомпонентНазначение
ПВХСправочник свойств (Цвет, Размер, Вес)
Тип значенияЧисло, строка, ссылка, булево
Доп. значенияКрасный, XL, 10 кг
Регистр сведенийОбъект + Свойство + Значение
ПВХ — мощный механизм расширяемости. Используется в УТ, ERP, КА.
📊
Планы счетов
Отдельный вид объекта под бухгалтерский учёт: 3 вида счёта, признаки учёта, субконто, предопределённые счета.
▼
План счетов — это отдельный вид объекта конфигурации, сделанный под бухгалтерский учёт. Внешне похож на справочник, но настроек больше: вид счёта, признаки учёта, субконто. Отличия от справочника: нет автонумерации, реквизит Порядок — это код, упорядочивание по коду. У счёта один из трёх видов: Активный, Пассивный или Активно-Пассивный. Используется в регистре бухгалтерии. Счета могут быть предопределёнными (в конфигураторе) или созданными пользователем.
ОсобенностьСправочникПлан счетов
НазначениеУниверсальные спискиТолько бухгалтерский учёт

Регистры — общие сведения
Хранилища данных для учёта: сведений, накопления, бухгалтерии, расчёта. Не имеют собственных форм.
▼
Регистры — это таблицы для накопления и хранения учётных данных. У них нет собственных форм, они заполняются через документы (регистраторы). Структура: Измерения (разрезы учёта), Ресурсы (что считаем), Реквизиты (доп. информация).

Накопления (обороты)Только обороты без остатковПродажи, выручка
БухгалтерииДвойная запись (дебет/кредит)Хозрасчётный, валютный
РасчётаСложные периодические расчётыНачисления зарплаты, отпускных

Регистр расчёта
Сложные периодические расчёты: зарплата, отпускные, больничные. Виды расчёта, базовый период, фактический период действия.
▼
Предназначен для расчётов, зависящих от других расчётов и периода действия. Самая сложная тема в 1С. Использует виды расчёта (оклад, премия, отпуск), базовый период (за какой период берутся данные) и фактический период действия (дни фактической работы).
ПонятиеОписание
Вид расчётаОклад, Премия, Отпуск, Больничный — настраиваются в ПВР
Базовый периодПериод, за который собираются базовые данные для расчёта
Фактический периодДни, когда расчёт фактически действовал (исключая выходные, отпуска)
ВытеснениеОдин вид расчёта может вытеснять другой (отпуск вытесняет оклад)

Планы видов расчёта (ПВР)
Оклад, премия, отпуск, больничный — виды начислений и удержаний для регистра расчёта.
▼
ПВР определяет виды расчётов, которые могут использоваться в регистре расчёта. Каждый вид имеет формулу, базовые виды расчёта, ведущие виды (от которых зависит) и вытесняющие виды (которые вытесняют).

Вытесняющие видыКто вытесняет (отпуск вытесняет оклад)

Проведение документа
Оперативное / неоперативное, безусловное / обусловленное проведение, движения по регистрам.
▼
Оперативное проведение — документ проводится "сейчас", контролируются остатки на текущий момент. Неоперативное — задним числом, остатки не контролируются (или контролируются на момент документа). Безусловное — всегда формирует движения. Обусловленное — движения зависят от условий.

Партионный учёт
Учёт товаров по партиям: ФИФО, ЛИФО, по средней. Регистр накопления с измерением "Партия".
▼
Партия — это документ поступления товара. Списание идёт по себестоимости конкретной закупки. Партионный учёт позволяет списывать товары по себестоимости конкретной закупки. Методы: ФИФО (первым пришёл — первым ушёл), по средней (средняя себестоимость).
МетодОписание

Способы записи движений по регистру
Движения.Регистр.Добавить(), набор записей, запись с отбором по регистратору.
▼
Движения можно формировать через коллекцию документа (Движения.Регистр.Добавить) — самый простой и стандартный способ. Или через набор записей — для сложной логики, когда нужно удалить старые движения и записать новые. Также можно записывать вне транзакции документа через менеджер регистра.
СпособКогда использовать

НаборЗаписей + Записать()Для независимых регистров сведений
МенеджерРегистра.СоздатьНаборЗаписей()Для программной записи вне документа

Механизм запросов
Встроенный язык запросов: ВЫБРАТЬ, ИЗ, ГДЕ, СГРУППИРОВАТЬ, УПОРЯДОЧИТЬ, ИТОГИ.
▼
Запросы — это язык для извлечения данных из БД. Основные операторы: ВЫБРАТЬ (поля), ИЗ (таблица), ГДЕ (фильтр), СГРУППИРОВАТЬ ПО (агрегация), УПОРЯДОЧИТЬ ПО (сортировка), ИТОГИ (итоги по группам).
ВЫБРАТЬ Номенклатура.Наименование КАК Товар, СУММА(Количество) КАК Всего ИЗ Документ.Реализация.Товары ГДЕ Дата МЕЖДУ &Начало И &Конец СГРУППИРОВАТЬ ПО Номенклатура.Наименование УПОРЯДОЧИТЬ ПО Всего УБЫВ ИТОГИ СУММА(Всего) ПО ОБЩИЕ
Всегда используй параметры (&Имя) вместо конкатенации строк — это защита от SQL-инъекций и кэширование плана запроса.
💻
Работа с запросами во встроенном языке
Новый Запрос, УстановитьПараметр, Выполнить, Выбрать, Выборка.Следующий().
▼
Запрос создаётся объектом Новый Запрос. Текст передаётся в свойство Текст. Параметры устанавливаются через УстановитьПараметр. Выполнение — Выполнить(). Результат обходится через Выбрать() + Выборка.Следующий().
Запрос = Новый Запрос; Запрос.Текст = "ВЫБРАТЬ | Номенклатура, | Количество |ИЗ | Документ.Реализация.Товары |ГДЕ | Ссылка = &Документ"; Запрос.УстановитьПараметр("Документ", ДокументСсылка); Результат = Запрос.Выполнить(); Выборка = Результат.Выбрать(); Пока Выборка.Следующий() Цикл Сообщить(Выборка.Номенклатура + ": " + Выборка.Количество); КонецЦикла; // Или сразу в таблицу значений ТЗ = Результат.Выгрузить();
Для небольших данных используй Выгрузить() в ТЗ — удобнее обработка. Для больших — Выбрать() с обходом, чтобы не грузить всё в память.
⚡
Оптимизация запросов
Индексы, виртуальные таблицы, условия на вирт. таблицах, избегайте ВЫБРАТЬ * и вложенных запросов.
▼
Условия на виртуальные таблицы передавай в параметрах таблицы, а не в ГДЕ. Избегай ВЫБРАТЬ * — выбирай только нужные поля. Не используй вложенные запросы вместо соединений. Индексы — платформа создаёт автоматически, но проверяй через план запроса.
ПравилоПлохоХорошо
Вирт. таблицаГДЕ Остатки.Склад = &СкладОстатки(, Склад = &Склад)
ПоляВЫБРАТЬ *ВЫБРАТЬ Номенклатура, Сумма
Вложенные запросыВЫБРАТЬ * ИЗ (ВЫБРАТЬ ...)Соединение таблиц
РегистраторГДЕ Регистратор = &ДокДвиженияССубконто(..., Регистратор = &Док)
// Плохо: фильтр в ГДЕ после выборки всех остатков ВЫБРАТЬ ... ИЗ РегистрНакопления.Товары.Остатки ГДЕ Склад = &Склад // Хорошо: фильтр в параметре виртуальной таблицы ВЫБРАТЬ ... ИЗ РегистрНакопления.Товары.Остатки(, Склад = &Склад)
Используй консоль запросов (в конфигураторе или внешней обработке) для отладки и анализа плана запроса.

Соединения и объединения
ЛЕВОЕ, ПРАВОЕ, ПОЛНОЕ, ВНУТРЕННЕЕ соединение + ОБЪЕДИНИТЬ ВСЕ.
▼
Соединение (JOIN) — объединяет столбцы из разных таблиц по условию. Объединение (UNION) — складывает строки из разных запросов. Виды соединений: ВНУТРЕННЕЕ (только совпадающие), ЛЕВОЕ (все из левой + совпадающие из правой).
ВидОписание
ВНУТРЕННЕЕ СОЕДИНЕНИЕТолько строки, есть в обеих таблицах
ЛЕВОЕ СОЕДИНЕНИЕВсе из левой + совпадающие из правой
ПРАВОЕ СОЕДИНЕНИЕВсе из правой + совпадающие из левой
ПОЛНОЕ СОЕДИНЕНИЕВсе строки из обеих таблиц
ОБЪЕДИНИТЬОбъединяет строки, убирает дубликаты
ОБЪЕДИНИТЬ ВСЕОбъединяет строки, сохраняет дубликаты
// Соединение: товары + остатки ВЫБРАТЬ Товары.Номенклатура, ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток ИЗ Справочник.Номенклатура КАК Товары ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Товары.Остатки КАК Остатки ПО Товары.Ссылка = Остатки.Номенклатура // Объединение: приход + расход ВЫБРАТЬ Номенклатура, Количество, "Приход" КАК Вид ИЗ Документ.Поступление.Товары ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ Номенклатура, Количество, "Расход" ИЗ Документ.Реализация.Товары
ЛЕВОЕ СОЕДИНЕНИЕ — самый частый тип. Используй ЕСТЬNULL для замены NULL на 0 или пустую строку.
СИСТЕМА КОМПОНОВКИ ДАННЫХ (СКД)
📊
СКД — основы
Наборы данных, связи, вычисляемые поля, ресурсы, параметры, настройки — отчёты без программирования.
▼
СКД — механизм построения отчётов. Набор данных (запрос, объект, объединение) → Связи (соединение наборов) → Вычисляемые поля (формулы) → Ресурсы (агрегация) → Параметры (входные данные) → Настройки (группировки, фильтры, сортировка).
ЭлементНазначение
Набор данныхИсточник: запрос, объект, объединение
Связи наборовСоединение нескольких наборов по полям
Вычисляемые поляПоля, рассчитываемые по формуле (Сумма * Курс)
РесурсыАгрегатные функции: Сумма, Количество, Среднее
ПараметрыВходные значения (период, организация)
НастройкиГруппировки, фильтры, порядок, условное оформление
СКД позволяет создавать сложные отчёты без написания кода. Пользователь сам настраивает группировки и фильтры.
🖥️
Программная работа с СКД
СхемаКомпоновкиДанных, КомпоновщикНастроек, ПроцессорКомпоновки, вывод в табличный документ.
▼
Для программного вывода отчёта нужно: 1) Получить СхемуКомпоновкиДанных, 2) Инициализировать КомпоновщикНастроек, 3) Создать ПроцессорКомпоновкиДанных, 4) Вывести через ПроцессорВывода в табличный документ.
// Получаем схему из макета Схема = Отчеты.МойОтчет.ПолучитьМакет("ОсновнаяСхемаКомпоновкиДанных"); // Настройки Настройки = Схема.НастройкиПоУмолчанию; // Компоновщик макета КомпоновщикМакета = Новый КомпоновщикМакетаКомпоновкиДанных; Макет = КомпоновщикМакета.Выполнить(Схема, Настройки); // Процессор компоновки Процессор = Новый ПроцессорКомпоновкиДанных; Процессор.Инициализировать(Макет); // Вывод ПроцессорВывода = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент; ПроцессорВывода.УстановитьДокумент(ТабличныйДокумент); ПроцессорВывода.Вывести(Процессор);
Для изменения настроек программно используй КомпоновщикНастроек.ДобавитьГруппировку() и установку отбора.
